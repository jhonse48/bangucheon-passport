# 반구천 탐험지도

지도를 화면 가로·세로 전체에 표시하는 **iPhone 설치형 관광 앱**입니다. 검색·필터·장소 카드·하단 메뉴를 지도 위에 배치합니다. Capacitor 8 앱 안에 정적 UI를 포함하고 네이버 지도, QR 퀴즈, 사진 관찰, 탐방 여권을 연결합니다. 원격 웹사이트를 시작 주소로 여는 앱이 아닙니다.

2026-10-23 사용자 요청에 따라 **현재 개발·검증·배포 대상은 iPhone(iOS)만**입니다. 기존 Android 프로젝트와 아래 관련 안내는 이전 작업 기록으로 보관하며 현재 진행 범위에 포함하지 않습니다.

2026-10-24에는 **오늘의 여정**을 추가하고 **날짜별 자동 경로 기록**으로 변경했습니다. iPhone에서 한 번 켜면 매번 시작·종료할 필요 없이 이동 경로와 사진을 기기에 모읍니다. 기록 중에도 지금까지의 여정을 MP4로 만들 수 있습니다. 수집함의 기존 ‘사진으로 남긴 발견’·‘나의 여행 메모’ 목록은 여정 요약으로 교체했으며 기존 데이터는 보존합니다. [여정 사용법·저장·복구·영상 규칙](docs/journeys.md)을 참고하세요.

**전체 13곳 지도·초기 화면 맞춤, A10/B3 코스, 13개 장소 퀴즈와 3개 사진 미션**은 유지합니다. 현장 QR 원본 URL을 모르는 상태에서도 장소를 골라 해설을 확인하고 관찰 문제로 이어갈 수 있습니다. A/B 점선은 방문 순서 연결선이며 실제 보행 경로가 아닙니다. 여정의 실선은 사용자가 기록한 GPS 구간입니다.

**자동 기록 전환 후 검사:** Node 테스트 **107개**, Swift XCTest **15개**, 타입·린트·프로덕션 빌드가 통과했습니다. 390×844 브라우저에서 ‘자동 기록 설정’·소개·설정 스위치·날짜별 이력과 브라우저의 비활성 스위치를 확인했으며 위치 권한은 요청하지 않았습니다. 최신 iOS 동기화·앱 빌드·업데이트 설치·실행이 통과했습니다. 실제 네이버 지도 13곳(12곳 묶음+1곳), 자동 기록 설정 버튼·오른쪽 버튼 3개·기존 스탬프 1개와 이전 수동 기록 보존을 확인했습니다. [자동 기록 iOS 화면](docs/ios-automatic-overview.png)과 [설정 소개 화면](docs/automatic-recording-preview.png)을 참고하세요. 브라우저의 가로 넘침·콘솔 경고/오류가 없었으며, 네이티브 권한 토글과 실제 이동 기록은 아직 검증하지 않았습니다. 아래 89/7 결과와 캡처는 같은 날의 수동 기록 버전 검증입니다.

**이전 검증 — 2026-10-24, 수동 기록 버전:** 전체 Node 테스트 **89개**, 네이티브 XCTest **7개**, 타입·린트 검사가 통과했습니다. 실제 H.264 MP4 생성·사진 픽셀·GPS 공백·스냅샷 하단 보존·자체 영상 캐시 삭제를 검사했습니다. 마지막 지도 버튼 배치 보정까지 빌드·iOS 동기화·업데이트 설치·실행을 완료했고, 실제 네이버 지도·13곳 표시(12곳 묶음과 1곳)·여정 바 아래 오른쪽 버튼 3개·기존 스탬프 1개 보존을 확인했습니다. [최종 iOS 시뮬레이터 화면](docs/ios-journey-overview.png)과 [브라우저 여정 소개](docs/journey-intro-preview.png)를 참고하세요. 브라우저에서는 수집함의 목록 교체·가로 넘침 없음, 인증 실패 시 앱이 종료되지 않는 연결 안내도 확인했습니다.

**이전 검증 — 2026-10-23:** 클러스터를 포함한 소스의 55개 테스트·타입·린트·차이 형식 검사·프로덕션/iOS 빌드·업데이트 설치가 통과했습니다. 시뮬레이터에서 13곳 범위, 9곳·2곳 묶음 마커, 교정된 반구대 위치와 기존 수집 1개 유지를 확인했습니다. [당시 지도 캡처](docs/ios-ab-overview.png)와 [날짜별 검증 결과](docs/implementation-status.md)를 참고하세요. 제공받은 Client ID는 Git에서 제외된 `.env.local`에 적용했습니다. 새 여정의 실제 iPhone 보행·잠금 상태 GPS·사진 앱 권한 검증은 남아 있습니다.

## 앱 빌드와 실행

설치된 **Node.js 24 LTS와 pnpm 12.15.0**을 기준으로 합니다. 저장소의 `packageManager`는 `pnpm@12.15.0`입니다. Node와 pnpm이 PATH에서 실행되는지 먼저 확인합니다. iOS에는 Xcode 26 이상이 추가로 필요합니다.

```bash
node --version
pnpm --version
pnpm install --frozen-lockfile
cp -n .env.example .env.local
```

새 체크아웃에서는 프로젝트 루트 `.env.local`에 네이버 Maps Client ID를 넣습니다. 현재 작업 폴더에는 제공받은 ID가 설정되어 있으므로 덮어쓰지 않습니다. 아래 값은 형식 예시이며 실제 키를 문서에 기록하지 않습니다.

```dotenv
NEXT_PUBLIC_NAVER_MAP_CLIENT_ID=your_maps_client_id
```

```bash
pnpm build
pnpm exec cap sync ios
pnpm exec cap run ios
```

`cap run ios`에서 실행 대상을 선택합니다. Xcode에서 실행하려면 `pnpm mobile:ios`로 프로젝트를 열고 `App` scheme과 시뮬레이터 또는 연결한 iPhone을 선택해 Run을 누릅니다. 실제 iPhone에는 Apple 개발 팀·서명·프로비저닝 및 기기의 개발자 모드 설정이 필요합니다. 이 저장소에는 개발 팀을 지정하지 않았습니다.

**`pnpm mobile:sync`** 또는 **`pnpm mobile:sync:ios`**는 정적 빌드 후 iOS만 동기화합니다. 위의 `pnpm build` → `pnpm exec cap sync ios`와 같은 흐름입니다. 화면·콘텐츠·환경변수 수정 후 앱을 다시 빌드하기 전에 동기화하세요. 앱 ID는 `kr.bangucheon.passport`, 표시 이름은 **반구천 탐험지도**입니다.

| 대상 | 실행·빌드 | 산출물·현재 상태 |
| --- | --- | --- |
| iOS 시뮬레이터 | `pnpm mobile:ios:build` | `.native-build/ios/Build/Products/Debug-iphonesimulator/App.app`. 10월 24일 자동 기록 포함 빌드·업데이트 설치·실행·지도/설정 진입 버튼 화면 확인 |
| 실제 iPhone | `pnpm mobile:ios` → Xcode에서 팀·기기 선택 후 Run | 서명 필요. 시뮬레이터 `.app`은 iPhone용 IPA가 아님 |
| Android 이전 작업 | 기존 프로젝트 보관 | 현재 개발·검증·배포 범위에서 제외. APK 없음 |

Swift Package Manager 기반 iOS 프로젝트여서 CocoaPods는 필요하지 않습니다. App Store 등록, 배포 서명과 스토어 심사는 완료하지 않았습니다. 자세한 환경과 권한 설명은 [iPhone 앱 안내](docs/mobile-app.md)에 있습니다.

## 네이버 지도 연결

[네이버 클라우드 플랫폼](https://www.ncloud.com/)의 Maps Application에서 **Dynamic Map 활성화**, 개발용 Web 서비스 URL 두 개(`http://localhost:3000`, `http://127.0.0.1:3000`), iOS Bundle ID **`kr.bangucheon.passport`**를 확인했습니다. **Client Secret은 앱이나 프런트엔드 환경변수에 넣지 않습니다.** 브라우저 지도는 신규 JavaScript SDK의 `ncpKeyId`를 사용하며 실제 타일 표시를 검증했습니다.

ID는 `.env.local` 또는 **지도 연결 설정**에 입력합니다. 화면 입력은 현재 세션의 `sessionStorage`에 보관하며 환경변수보다 우선합니다. 배포용 ID는 빌드 환경변수로 설정하고 재빌드·iOS 동기화를 수행합니다. `.env.local`은 Git에서 제외하며 키 값은 문서·진단 출력에 적지 않습니다.

브라우저는 Web 서비스 URL로 인증합니다. iPhone의 기존 `capacitor://` WebView에서는 JavaScript SDK의 HTTP 하위 요청이 ATS에 차단되는 오류(`-1022`)가 발생해, 등록된 Bundle ID를 사용하는 **공식 iOS 네이티브 지도 SDK**로 전환했습니다. 시뮬레이터에서 네이티브 SDK 인증과 실제 타일 표시를 확인했습니다. `capacitor://` Web 서비스 URL 추가나 ATS 완화는 사용하지 않았으며 콘솔의 외부 설정도 추가 저장하지 않았습니다. 앱의 기존 origin과 저장소를 유지해 수집 배지 1개도 보존했습니다. 자세한 구조는 [지도 설정 문서](docs/map-setup.md)에 있습니다.

다른 환경에서 Client ID가 없거나 연결에 실패하면 중립 배경의 **지도 연결 안내**를 표시합니다. 가짜 지도 타일이나 지도처럼 보이는 일러스트로 대신하지 않습니다. 장소 목록·미션·공식 링크·수집함은 계속 사용할 수 있습니다. 네이티브 마커 터치·미션 패널 전환과 실제 기기의 현재 위치 동작은 추가 검증 대상입니다.

`src/data/exploration.ts`에서 **13곳의 출처·좌표·정확도·현장 QR 상태**를 관리합니다. 공식/공개 지도 대표 위치 9곳과 공식 분포도를 대조한 근사 위치 4곳을 구분합니다. 안전 관람 좌표인 `viewingPosition`은 모두 `null`입니다. 반구대 마커는 조망 공간 일대의 근사 위치이며 암면의 유산 좌표와 분리합니다. 이전 반구대·천전리 좌표는 최신 근거로 교정했습니다. [좌표와 QR 조사 근거](docs/exploration-evidence.md)를 참고하세요.

첫 화면은 13개 지점이 보이도록 맞춥니다. 코스를 선택하면 해당 방문 순서로 번호와 점선을 표시하고 코스 범위를 맞추며, 전환·해제 때 이전 선을 정리합니다. 검색·미션 필터가 코스 연결선의 순서를 바꾸지는 않습니다. iOS는 화면상 가까운 마커를 “몇 곳”으로 묶고 장소 선택 목록을 연결합니다. 실제 좌표를 옮기지 않으며 장소 카드에서도 각각 선택할 수 있습니다. 묶음 표시를 확인했고 실제 묶음 터치 흐름은 추가 검증 대상입니다. 외부 네이버 지도는 장소명 검색으로 연결합니다.

## 화면과 탐험

첫 화면은 화면 전체 지도이며 검색·필터, 선택 장소의 하단 카드와 미션 패널을 그 위에 제공합니다. 하단 메뉴는 **지도 · QR · 수집** 3개입니다. iOS는 지도 위에 투명 WebView를 배치해 메뉴·버튼 터치는 웹 UI가 처리하고 나머지 지도 터치는 네이티브 지도로 전달합니다. 모달·입력창을 사용할 때는 지도를 배경에 유지하면서 지도 조작을 막습니다. 전체 화면 지도 표시는 확인했으며 이 터치 분리의 실사용 검증은 남아 있습니다. 처음 앱을 열거나 기록을 조회하는 것만으로 위치·카메라 권한을 요청하지 않습니다. 자동 기록을 켠 뒤에는 저장된 설정과 현재 권한에 따라 위치 서비스를 복원합니다.

- **지도:** 장소·미션 검색, 전체/QR 퀴즈/사진 관찰/완료 필터, 코스 선택, 장소 상세와 공식 해설·교통·체험 안내.
- **QR:** 현장 해설 안내판을 찾을 장소 선택 → 해설 확인 → 관찰 미션. 별도로 앱 체험용 QR 스캔·코드 입력도 제공.
- **수집:** 레벨·XP, 장소 스탬프, 바위그림 도감, 오늘의 여정·지난 여정, 내보내기·삭제. 기존 장소 메모는 장소 상세에서 유지.

### 오늘의 여정 — 2026-10-24

지도 위 여정 바 또는 수집함의 **오늘의 여정 → 자동 경로 기록**을 한 번 켭니다. 앱 밖에서도 기록하려면 **백그라운드 위치 허용**으로 iPhone의 위치 접근을 **항상**으로 허용합니다. 정확한 경로에는 **정확한 위치**가 필요합니다. 이후 기록은 한국 날짜(Asia/Seoul)별로 나뉘며 매번 시작·종료하지 않습니다. 끄면 수집을 멈추고 저장된 기록은 남깁니다. 이전에 직접 시작한 여정과 기록도 보존합니다.

- 실제 수신한 경로와 사진 위치를 지도에 표시합니다. A/B 점선·장소 클러스터와 분리하며, 재개나 120초 초과 GPS 공백은 선으로 잇지 않습니다. 새 위치마다 지도 시점을 강제로 바꾸지 않습니다.
- **여정 사진 찍기**와 사진 미션은 카메라를 열기 전에 대상 기록을 확정합니다. 촬영 위치를 확인하지 못하면 사진은 앨범·영상에만 넣으며 지도 좌표를 만들지 않습니다. 날짜가 바뀌어 대상 기록이 달라지면 다른 날짜에 임의 저장하지 않고 원본 사진 저장을 제공합니다.
- **지금까지 영상 만들기 · MP4**는 자동 기록을 중단하지 않고 버튼을 누른 시점의 사본을 기기 안에서 합성합니다. 지난 기록도 영상으로 만들 수 있습니다. 실제 사진 최대 60장, H.264·720×1280·24fps·20~45초·무음 영상입니다. 네이버 공식 SDK 스냅샷이 성공하면 출처를 포함한 전체 지도를 쓰고, 실패하면 ‘기록 좌표를 연결한 그림’으로 명시한 대체 영상을 만듭니다.
- 영상은 **사진 앱에 동영상 저장** 또는 **파일로 저장 · 공유**로 내보냅니다. 외부에 저장한 복사본은 앱에서 여정을 삭제해도 남습니다.

자동 기록은 관광지 밖의 이동도 저장합니다. iOS는 Always 권한과 저전력 위치 변경 감시로 시스템 종료 뒤 복구를 시도하지만, 사용자가 앱을 밀어 강제 종료한 뒤 자동 재개하거나 빠진 경로를 복원한다고 보장하지 않습니다. 실제 iPhone의 잠금·장시간 이동·배터리·권한 변경은 아직 미검증입니다. 자동 기록은 iPhone 앱 전용이며 브라우저에서는 설정·이력을 미리 봅니다. [여정 문서](docs/journeys.md)에 저장·복구와 운영체제 제한을 정리했습니다.

관광지 **13곳 모두 장소 퀴즈를 제공**합니다. 초기 기획의 시범 6곳 표시는 과거 범위이며 현재 미션 접근을 제한하지 않습니다. 저장된 4개 코스 중 A/B 2개를 활성화하고 나머지 확장 코스는 보류합니다.

| 코스 | 방문 순서 |
| --- | --- |
| A · 반구대 방향 10곳 | 박물관 → 집청정 → 반구서원 → 포은대 → 모은정 → 유허비 → 연로 개수기 → 자연습지 → 대곡리 공룡발자국 → 반구대 조망지점 |
| B · 천전리 방향 3곳 | 천전리 명문과 암각화 → 천전리 공룡발자국 → 대곡박물관 |

현장 QR 상태는 **안내판 사진 확인 1곳(반구대), 위치·개별 설치 확인 필요 10곳, 사용자 조사표의 QR 대상이 아닌 박물관 2곳**입니다. 사진 확인도 현재 작동·원본 URL·정확한 부착 GPS 확인을 뜻하지 않습니다. 지도 `QR`/`QR?` 표시는 이 상태이며 앱 체험용 QR 발급 여부와 별개입니다.

### 장소 퀴즈 13개 · 사진 관찰 3개

| 미션 | 완료 조건 | 보상 |
| --- | --- | --- |
| 장소 퀴즈 13개 | 해설 확인을 스스로 체크하거나 앱 체험용 QR/코드로 해제한 뒤 정답 저장 | 각 80 XP |
| 사진 관찰 3개 | 사진 + 허용된 관찰 대상 선택 + 1~2,000자 메모 저장 | 각 120 XP |

16개를 모두 완료하면 **1,400 XP·레벨 5·장소 스탬프 13개·수집 카드 13개**입니다. 해설 확인·QR 해제만으로는 보상이 없으며, 같은 미션을 반복 완료해도 추가 지급하지 않습니다. 기존 6개 퀴즈·3개 사진 미션 ID와 저장소를 유지해 이전 완료 기록을 새 미션으로 중복 계산하지 않습니다.

현장 QR 원본 URL이 아직 확보되지 않아 스캔한 시설 QR을 자동으로 장소·보상에 연결하지 않습니다. **QR 메뉴에서 장소 선택 → 현장 또는 공식 해설 확인 → “관찰 문제 풀기”**로 진행합니다. 해설 확인은 자기 확인이며 QR 스캔·현장 방문 인증이 아닙니다.

사진 미션은 박물관·반구대·천전리에서 제공하며 휴대폰 카메라를 연결했습니다. 사진에 고래가 있는지 자동 인식하거나 XR·망원경 사용·현장 방문을 인증하지 않습니다. 관찰 대상은 사용자가 고르는 자기 기록입니다. 사진은 촬영이 허용된 구역에서 남기고, 반구대 암면으로 접근하거나 하천을 건너지 않습니다.

체험용 QR은 앱에서 발급한 공개 코드입니다. 공식 관광 시설에 이미 설치되어 있다고 가정하지 않습니다. 코드 목록과 입력 규칙은 [QR·사진 미션 문서](docs/qr-missions.md)에 있습니다. **미션을 하지 않아도 관광 정보를 이용할 수 있습니다.**

## 기록 보존·삭제·내보내기

로그인 없이 IndexedDB에 저장합니다. 게임은 `bangucheon-game`, 기존 탐방 여권은 `bangucheon-passport`, 새 여정은 `bangucheon-journeys` 데이터베이스를 사용합니다. 기존 여권의 사진·메모·방문 체크·선택 코스를 보존하며 새 게임 XP는 새 완료 미션에서 계산합니다. iOS는 재실행 복구용 GPS 버퍼도 기기에 보관합니다. 이전 브라우저 기록이 네이티브 앱으로 자동 이전되지는 않습니다.

- 기존 메모·사진은 장소 상세에서 추가·수정·삭제할 수 있습니다. 사진 입력은 JPG·PNG·WebP, 20MB 이하이며 긴 변 최대 1600px로 처리합니다.
- 사진 미션 취소·필수 항목 누락·잘못된 정답·저장 실패에는 XP를 지급하지 않습니다. 완료 미션을 삭제하면 관련 XP를 다시 계산합니다.
- 장소별 삭제는 해당 장소의 기존 기록과 게임 기록·QR 해제를 지웁니다. 여정 삭제는 해당 경로·사진·앱 내부 영상 캐시를 지우며 미션 보상은 유지합니다. 전체 삭제는 추적을 중단하고 네이티브 버퍼·영상 캐시·세 저장소를 지웁니다. 여러 저장소를 합친 단일 트랜잭션은 없으며 오류가 발생하면 성공으로 표시하지 않습니다.
- **사진과 기록 내보내기**는 세 저장소의 기록·여정 좌표·사진 Base64를 포함하는 JSON을 준비합니다. 네이티브 앱에서는 **OS 공유 시트**를 열어 사용자가 저장·공유할 대상을 선택합니다. 미리보기에서는 파일로 다운로드합니다. 외부에 내보낸 파일은 앱 기록 삭제로 지워지지 않습니다.
- 기록과 사진을 앱 자체 서버에 업로드하지 않습니다. 지도 표시·스냅샷·외부 안내에는 네트워크가 필요합니다. **내 위치**는 일회성 읽기이며 **자동 경로 기록**은 한 번 켠 뒤 끌 때까지 권한과 시스템 상태에 따라 이어지는 기록입니다. 어느 쪽도 현장 방문 인증이 아닙니다.
- 앱 삭제·앱 데이터 초기화·기기 변경 시 기록을 잃을 수 있습니다. JSON 가져오기·계정 동기화는 아직 없습니다.
