# 반구천 탐험지도

지도를 화면 가로·세로 전체에 표시하는 **iPhone 설치형 관광 앱**입니다. 검색·필터·장소 카드·하단 메뉴를 지도 위에 배치합니다. Capacitor 8 앱 안에 정적 UI를 포함하고 네이버 지도, QR 퀴즈, 사진 관찰, 탐방 여권을 연결합니다. 원격 웹사이트를 시작 주소로 여는 앱이 아닙니다.

2026-10-23 사용자 요청에 따라 **현재 개발·검증·배포 대상은 iPhone(iOS)만**입니다. 기존 Android 프로젝트와 아래 관련 안내는 이전 작업 기록으로 보관하며 현재 진행 범위에 포함하지 않습니다.

2026-10-23 공식 Naver Maps iOS SDK 3.24.0과 투명 WebView를 통합한 앱을 설치해, **상태 표시줄 뒤부터 하단 끝까지 실제 지도 타일·공식 마커 3개가 화면을 채우는 것을 확인**했습니다. iPhone 17 Pro / iOS 26.5 시뮬레이터 기준이며 44개 테스트와 타입·린트·웹/iOS 빌드를 통과했습니다. 확대축소 버튼은 사진 미션과 분리해 왼쪽에 배치했고 로고와 축척도 겹치지 않습니다. [최종 전체 화면 지도](docs/ios-fullscreen-map.png)와 [구현·검증 상태](docs/implementation-status.md)를 확인할 수 있습니다. 제공받은 Client ID는 Git에서 제외된 `.env.local`에 적용했습니다.

## 앱 빌드와 실행

설치된 **Node.js 24 LTS와 pnpm 12.15.0**을 기준으로 합니다. 저장소의 `packageManager`는 `pnpm@12.15.0`입니다. Node와 pnpm이 PATH에서 실행되는지 먼저 확인합니다. iOS에는 Xcode 26 이상이 추가로 필요합니다.

```bash
node --version
pnpm --version
pnpm install --frozen-lockfile
cp -n .env.example .env.local
```

새 체크아웃에서는 프로젝트 루트 `.env.local`에 네이버 Maps Client ID를 넣습니다. 현재 작업 폴더에는 제공받은 ID가 설정되어 있으므로 덮어쓰지 않습니다. 아래 값은 형식 예시이며 실제 키를 문서에 기록하지 않습니다.

```dotenv
NEXT_PUBLIC_NAVER_MAP_CLIENT_ID=your_maps_client_id
```

```bash
pnpm build
pnpm exec cap sync ios
pnpm exec cap run ios
```

`cap run ios`에서 실행 대상을 선택합니다. Xcode에서 실행하려면 `pnpm mobile:ios`로 프로젝트를 열고 `App` scheme과 시뮬레이터 또는 연결한 iPhone을 선택해 Run을 누릅니다. 실제 iPhone에는 Apple 개발 팀·서명·프로비저닝 및 기기의 개발자 모드 설정이 필요합니다. 이 저장소에는 개발 팀을 지정하지 않았습니다.

**`pnpm mobile:sync`** 또는 **`pnpm mobile:sync:ios`**는 정적 빌드 후 iOS만 동기화합니다. 위의 `pnpm build` → `pnpm exec cap sync ios`와 같은 흐름입니다. 화면·콘텐츠·환경변수 수정 후 앱을 다시 빌드하기 전에 동기화하세요. 앱 ID는 `kr.bangucheon.passport`, 표시 이름은 **반구천 탐험지도**입니다.

| 대상 | 실행·빌드 | 산출물·현재 상태 |
| --- | --- | --- |
| iOS 시뮬레이터 | `pnpm mobile:ios:build` | `.native-build/ios/Build/Products/Debug-iphonesimulator/App.app`. 10월 23일 전체 화면 지도·최종 컨트롤 배치의 빌드·설치·실제 타일·3개 마커 표시 확인 |
| 실제 iPhone | `pnpm mobile:ios` → Xcode에서 팀·기기 선택 후 Run | 서명 필요. 시뮬레이터 `.app`은 iPhone용 IPA가 아님 |
| Android 이전 작업 | 기존 프로젝트 보관 | 현재 개발·검증·배포 범위에서 제외. APK 없음 |

Swift Package Manager 기반 iOS 프로젝트여서 CocoaPods는 필요하지 않습니다. App Store 등록, 배포 서명과 스토어 심사는 완료하지 않았습니다. 자세한 환경과 권한 설명은 [iPhone 앱 안내](docs/mobile-app.md)에 있습니다.

## 네이버 지도 연결

[네이버 클라우드 플랫폼](https://www.ncloud.com/)의 Maps Application에서 **Dynamic Map 활성화**, 개발용 Web 서비스 URL 두 개(`http://localhost:3000`, `http://127.0.0.1:3000`), iOS Bundle ID **`kr.bangucheon.passport`**를 확인했습니다. **Client Secret은 앱이나 프런트엔드 환경변수에 넣지 않습니다.** 브라우저 지도는 신규 JavaScript SDK의 `ncpKeyId`를 사용하며 실제 타일 표시를 검증했습니다.

ID는 `.env.local` 또는 **지도 연결 설정**에 입력합니다. 화면 입력은 현재 세션의 `sessionStorage`에 보관하며 환경변수보다 우선합니다. 배포용 ID는 빌드 환경변수로 설정하고 재빌드·iOS 동기화를 수행합니다. `.env.local`은 Git에서 제외하며 키 값은 문서·진단 출력에 적지 않습니다.

브라우저는 Web 서비스 URL로 인증합니다. iPhone의 기존 `capacitor://` WebView에서는 JavaScript SDK의 HTTP 하위 요청이 ATS에 차단되는 오류(`-1022`)가 발생해, 등록된 Bundle ID를 사용하는 **공식 iOS 네이티브 지도 SDK**로 전환했습니다. 시뮬레이터에서 네이티브 SDK 인증과 실제 타일 표시를 확인했습니다. `capacitor://` Web 서비스 URL 추가나 ATS 완화는 사용하지 않았으며 콘솔의 외부 설정도 추가 저장하지 않았습니다. 앱의 기존 origin과 저장소를 유지해 수집 배지 1개도 보존했습니다. 자세한 구조는 [지도 설정 문서](docs/map-setup.md)에 있습니다.

다른 환경에서 Client ID가 없거나 연결에 실패하면 중립 배경의 **지도 연결 안내**를 표시합니다. 가짜 지도 타일이나 지도처럼 보이는 일러스트로 대신하지 않습니다. 장소 목록·미션·공식 링크·수집함은 계속 사용할 수 있습니다. 네이티브 마커 터치·미션 패널 전환과 실제 기기의 현재 위치 동작은 추가 검증 대상입니다.

공식 울산관광 링크에서 확인한 박물관·반구대·천전리의 **대표 위치 3곳**을 별도 지도 데이터로 관리합니다. 유산 마커는 **관람 지점 아님**, 박물관은 **출입구 확인 필요**로 구분합니다. 안전 관람 좌표는 아직 `null`이며, 외부 네이버 지도 링크는 장소명 검색입니다. 대표 좌표를 안전한 길찾기 목적지로 보내거나 미검증 경로선을 그리지 않습니다.

## 화면과 탐험

첫 화면은 화면 전체 지도이며 검색·필터, 선택 장소의 하단 카드와 미션 패널을 그 위에 제공합니다. 하단 메뉴는 **지도 · QR · 수집** 3개입니다. iOS는 지도 위에 투명 WebView를 배치해 메뉴·버튼 터치는 웹 UI가 처리하고 나머지 지도 터치는 네이티브 지도로 전달합니다. 모달·입력창을 사용할 때는 지도를 배경에 유지하면서 지도 조작을 막습니다. 전체 화면 지도 표시는 확인했으며 이 터치 분리의 실사용 검증은 남아 있습니다. 앱 시작 시 카메라나 위치 권한을 요청하지 않습니다.

- **지도:** 장소·미션 검색, 전체/QR 퀴즈/사진 관찰/완료 필터, 코스 선택, 장소 상세와 공식 해설·교통·체험 안내.
- **QR:** 앱 체험용 QR 스캔 또는 짧은 코드 입력으로 퀴즈 해제. 공식 시설 QR이나 방문 인증과 구분.
- **수집:** 레벨·XP, 장소 스탬프, 바위그림 도감, 관찰 사진, 기존 여행 메모, 내보내기·삭제.

관광지 기본 데이터는 **13곳**, 시범 장소는 **6곳**입니다. 울산암각화박물관, 집청정, 반구서원, 대곡리 공룡발자국, 반구대 암각화 조망지점, 천전리 명문과 암각화가 시범 대상입니다. **4개 코스 중 핵심·천전리 2개**만 활성화했습니다. 나머지 장소와 확장 코스는 현장 확인 후 활성화합니다.

### QR 퀴즈 6개 · 사진 관찰 3개

| 미션 | 완료 조건 | 보상 |
| --- | --- | --- |
| QR 퀴즈 6개 | 등록된 앱 체험용 QR/코드로 해제한 뒤 정답 저장 | 각 80 XP |
| 사진 관찰 3개 | 사진 + 허용된 관찰 대상 선택 + 1~2,000자 메모 저장 | 각 120 XP |

9개를 모두 완료하면 **840 XP·레벨 5·장소 스탬프 6개·수집 카드 6개**가 됩니다. QR 해제만으로는 XP가 지급되지 않고 같은 미션을 반복 완료해도 추가 지급되지 않습니다. 자기 방문 체크는 미션 보상과 별개입니다.

사진 미션은 박물관·반구대·천전리에서 제공하며 휴대폰 카메라를 연결했습니다. 사진에 고래가 있는지 자동 인식하거나 XR·망원경 사용·현장 방문을 인증하지 않습니다. 관찰 대상은 사용자가 고르는 자기 기록입니다. 사진은 촬영이 허용된 구역에서 남기고, 반구대 암면으로 접근하거나 하천을 건너지 않습니다.

체험용 QR은 앱에서 발급한 공개 코드입니다. 공식 관광 시설에 이미 설치되어 있다고 가정하지 않습니다. 코드 목록과 입력 규칙은 [QR·사진 미션 문서](docs/qr-missions.md)에 있습니다. **미션을 하지 않아도 관광 정보를 이용할 수 있습니다.**

## 기록 보존·삭제·내보내기

로그인 없이 IndexedDB에 저장합니다. 새 게임은 `bangucheon-game`, 기존 탐방 여권은 `bangucheon-passport` 데이터베이스를 사용합니다. 기존 여권의 사진·메모·방문 체크·선택 코스를 보존하며 새 게임 XP는 새 완료 미션에서 계산합니다. 이전 브라우저 기록이 네이티브 앱으로 자동 이전되지는 않습니다.

- 기존 메모·사진은 장소 상세에서 추가·수정·삭제할 수 있습니다. 사진 입력은 JPG·PNG·WebP, 20MB 이하이며 긴 변 최대 1600px로 처리합니다.
- 사진 미션 취소·필수 항목 누락·잘못된 정답·저장 실패에는 XP를 지급하지 않습니다. 완료 미션을 삭제하면 관련 XP를 다시 계산합니다.
- 장소별 삭제는 해당 장소의 기존 기록과 새 게임 기록·QR 해제를 지웁니다. 전체 삭제는 두 저장소를 모두 대상으로 합니다. 두 DB를 합친 단일 트랜잭션은 없으며 오류가 발생하면 성공으로 표시하지 않습니다.
- **사진과 기록 내보내기**는 두 저장소와 사진 Base64를 포함하는 JSON을 준비합니다. 네이티브 앱에서는 **OS 공유 시트**를 열어 사용자가 저장·공유할 대상을 선택합니다. 미리보기에서는 파일로 다운로드합니다. 외부에 내보낸 파일은 앱 기록 삭제로 지워지지 않습니다.
- 기록과 사진을 앱 서버에 전송하지 않습니다. 지도·외부 안내에는 네트워크가 필요합니다. 현재 위치는 버튼으로 요청하는 일회성 읽기이며 백그라운드 추적·방문 인증에 쓰지 않습니다.
- 앱 삭제·앱 데이터 초기화·기기 변경 시 기록을 잃을 수 있습니다. JSON 가져오기·계정 동기화는 아직 없습니다.

## 개발 미리보기와 검사

브라우저는 UI 개발용 보조 미리보기입니다. `pnpm dev` 실행 후 **http://localhost:3000**을 열면 됩니다. 실제 카메라 QR 스캔은 네이티브 앱에서 제공하며 미리보기에서는 코드 입력을 사용합니다. 네이티브 촬영·공유·위치 동작을 브라우저 검사만으로 검증하지 않습니다.

| 명령 | 역할 |
| --- | --- |
| `pnpm dev` | 로컬 UI 개발 미리보기 |
| `pnpm typecheck` | TypeScript 검사 |
| `pnpm lint` | ESLint 검사 |
| `pnpm test` | 게임·QR·사진 입력·저장소·콘텐츠·네이버 지도 헬퍼 테스트 |
| `pnpm build` | Next.js 정적 자산 `out/` 생성 |
| `pnpm start` | 빌드된 정적 UI의 보조 미리보기 |
| `pnpm mobile:sync` / `pnpm mobile:sync:ios` | 정적 빌드 후 iOS에만 동기화 |
| `pnpm exec cap sync ios` | 빌드된 자산과 플러그인을 iOS에 동기화 |
| `pnpm mobile:ios` | Xcode 프로젝트 열기 |

2026-10-23 전체 화면 지도를 포함한 **자동 테스트 44개, 타입 검사, 린트, Next.js 프로덕션 빌드와 Xcode 시뮬레이터 빌드가 통과**했습니다. iOS 동기화·최종 업데이트 설치 후 상태 표시줄 뒤부터 하단 끝까지 실제 타일과 3개 마커가 표시되고, 오른쪽의 빈 띠가 제거된 것을 확인했습니다. 검색·필터·미션·하단 카드·탭은 지도 위에 표시되며 확대축소·사진 미션·로고·축척도 서로 겹치지 않게 배치했습니다. [최종 캡처](docs/ios-fullscreen-map.png)는 시뮬레이터의 실제 실행 화면입니다. 이전 SDK 연결 검사에서는 축척 200m → 500m 변경과 브라우저 지도 표시도 확인했습니다.

이전 검증에서는 좌표 터치 도구가 `noWindowsAvailable` 오류를 반복해 마커 → 미션·모달 흐름을 끝까지 검증하지 못했습니다. 새 구조는 모달을 지도 위에 표시하고 지도 터치만 차단합니다. 지도 드래그·핀치와 웹 버튼·패널의 터치 분리, 실제 iPhone 카메라·QR 스캐너·GPS와 반복 재실행은 추가 검증 대상입니다.

2026-10-22의 지도 키 적용 전 앱에서는 타입·린트·37개 테스트·프로덕션/시뮬레이터 빌드를 통과했습니다. 설치된 앱에서 박물관 퀴즈 정답 후 **80 XP·스탬프 1/6·미션 1/9·카드 1개**, 완전 종료 후 재실행 시 기록 보존, 로컬 개발 서버 없는 실행을 확인했습니다. 이 기록을 새 지도 SDK의 성공으로 해석하지 않습니다.

10월 22일 첫 실행에서 검은 화면을 한 차례 관찰했고 재진입·이후 완전 종료 후 재실행은 통과했습니다. 그 관찰의 원인은 확정하지 않았으며 이번 ATS 지도 오류와 같은 원인이라고 단정하지 않습니다. [구현 현황](docs/implementation-status.md)에 날짜별 확인 범위와 캡처를 기록합니다.

### 새 버전 인수 시나리오

1. **A — 지도·장소:** 앱 실행 → 지도 첫 화면 → 장소 검색·코스 선택 → 하단 장소 카드 → 공식 설명·네이버 검색. 키가 없으면 연결 안내가 표시되고 장소 목록을 계속 이용할 수 있어야 합니다.
2. **B — QR·보상:** 앱 체험용 `BG-MUSEUM-26` 입력 또는 실제 기기로 QR 스캔 → 퀴즈 해제 → 오답에서는 보상 없음 → 정답 저장 후 80 XP·스탬프 확인 → 재실행 후 유지·반복 완료 중복 지급 없음.
3. **C — 사진·기록:** 실제 기기로 촬영 → 대상·메모 입력 → 저장 후 120 XP 확인 → 앱 재실행 → 사진·메모 보존 확인. 취소·누락은 보상 없음. 기존 여행 메모 수정, OS 공유 내보내기, 장소·전체 삭제도 확인합니다.
4. **D — 위치·권한:** 등록한 Client ID·iOS Bundle ID로 네이티브 지도 SDK 인증 → 내 위치 허용·거부 확인 → 카메라 허용·거부·취소 → 실패 후에도 장소와 기록 이용. 시뮬레이터 카메라 부재와 실제 기기 동작을 구분합니다.
