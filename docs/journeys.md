# 나의 여정: 날짜별 자동 경로·사진·MP4

2026-10-24 자동 기록 변경 기준. iPhone에서 사용자가 한 번 켠 뒤 이동 기록을 날짜별로 보관한다. A/B 코스 점선은 방문 순서 안내선이고 여정 실선은 실제 기기에서 받은 좌표다. 관광지 방문 인증이나 안전한 보행 경로 안내는 아니다.

## 사용 흐름

1. 지도 여정 바 또는 수집함의 **오늘의 여정 → 자동 기록 설정**을 열어 **자동 경로 기록**을 켠다. 처음에는 꺼져 있으며, 과거 수동 기록이 있다고 자동으로 켜지지 않는다.
2. iPhone 위치 권한을 허용한다. 앱 밖에서도 복구·기록하려면 별도의 **백그라운드 위치 허용** 버튼으로 위치 접근을 **항상**으로 설정한다. 상세 경로에는 **정확한 위치**가 필요하다. 허용하지 않아도 기존 기록은 열 수 있다.
3. 매번 시작·종료하지 않는다. 첫 실제 위치나 명시적 사진 촬영을 위한 기록 준비부터 **한국 날짜(Asia/Seoul)**별 기록을 만든다. 날짜가 바뀌면 이전 날을 보관하고 다음 날 기록을 이어간다. 위치·사진이 없는 날을 이력으로 만들지 않는다.
4. **여정 사진 찍기** 또는 사진 미션에서 촬영하면 해당 날짜의 기록에 보관한다. 카메라·파일 선택기를 열기 전에 대상 ID를 확정한다. 촬영 위치를 확인하지 못한 사진과 파일에서 고른 사진은 앨범·영상에만 포함하고 지도 핀을 만들지 않는다.
5. **지금까지 영상 만들기 · MP4**는 기록을 멈추지 않는다. 버튼을 누른 시점의 사본으로 영상을 만든다. 날짜별 이력도 열어 경로·사진을 보거나 영상으로 만들 수 있다. 생성 중에는 앱을 열어 둔다.
6. 자동 기록을 끄면 위치 수집을 중단하고 저장한 경로·사진은 남긴다. 다시 켜면 날짜에 맞는 기록에서 새 구간을 시작한다. 이전에 직접 시작한 수동 여정은 별도 이력으로 유지하며 기존 일시정지·재개·보관 버튼을 제공한다.

자동 기록은 관광지 밖의 이동도 저장한다. 기록 조회는 카메라를 열지 않으며, 자동 기록을 끈 상태에서 앱을 열었다고 위치 추적을 새로 시작하지 않는다. 자동 기록은 iPhone 앱 전용이다. 브라우저는 화면·이력을 확인하는 보조 환경이며 백그라운드 타임라인을 제공하지 않는다.

저장 실패는 성공으로 처리하지 않는다. 저장하지 못한 사진은 같은 여정에 재시도하거나 **원본 사진 파일로 저장**할 수 있다. 촬영 중 날짜·세션이 바뀌면 다른 여정에 임의로 옮기지 않는다. 재시도 때 현재 위치를 과거 촬영 위치로 붙이지 않으며, 저장 후 화면 동기화만 실패한 사진도 중복 저장하지 않는다. 저장 대기 사진은 앱 메모리에 있으므로 강제 종료 뒤 남는다고 보장하지 않는다.

기존 여정의 ID·사진·좌표는 유지한다. `mode`가 없는 이전 기록은 수동 여정으로 취급한다. 새 기록은 `mode: automatic`, `dayKey`, 시작/종료 시각, `recording/paused/completed`, 좌표와 사진을 가진다. 좌표에는 위·경도, 밀리초 시각, 정확도(m), 구간 번호가 있고 사진에는 압축 Blob·미리보기·촬영 시각·확인한 위치 또는 `null`이 있다. 게임·여권 DB와 분리한다.

iOS는 `Application Support/JourneyNative/tracking.json`에 자동 설정, 현재 기록과 미동기화 일자 버퍼를 보관한다. 네이티브 서비스가 WebView와 독립적으로 기록하며, JS가 활성화되면 현재·지난 버퍼를 하나의 IndexedDB 트랜잭션으로 합친다. 커밋한 뒤에만 `acknowledgeArchived`로 지난 버퍼 삭제를 허용한다. 같은 센서 타임스탬프는 중복 저장하지 않는다. 저장에 실패하면 확인 응답을 보내지 않아 원본 버퍼를 유지한다.

자동 기록 의도와 현재 권한·수집 상태는 별개다. 켬 설정과 권한이 유효할 때 서비스를 복원하고, 수동 여정은 이전처럼 일시정지로 복구한다. 날짜 전환은 실제 이벤트·조회 시각을 기준으로 처리하며 자정에 OS가 반드시 앱을 실행한다고 가정하지 않는다. 저장 실패나 안전 중단은 `recoveryHold`를 디스크와 설정에 남겨 앱 재실행·큰 이동 신호로 자동 재개하지 않게 한다. 사용자가 다시 켜거나 재개할 때 해제한다. 삭제한 ID의 늦은 이벤트가 기록을 되살리지 않도록 위치·사진 없는 삭제 표지를 보관한다.

주요 브리지 호출은 `setAutomaticTracking({enabled})`, `requestBackgroundAuthorization()`, `ensureAutomaticJourney()`, `getTrackingState()`, `acknowledgeArchived({journeyIds})`다. 추적 이벤트는 오래된 상태를 바로 적용하지 않고 최신 네이티브 상태를 다시 읽게 한다. `videoSnapshot(id)`는 원본을 종료하지 않고 영상용 사본만 완료 상태로 만든다.

## 위치 정확도와 iOS 제한

수신 좌표는 정확도 0m 초과·50m 이하, 유효한 좌표·시간 순서 등을 검사한다. 새 네이티브 센서 값은 최근 30초 이내여야 하며 비정상 점프와 정지 흔들림을 제외한다. 차량·철도 이동을 허용하도록 속도 상한은 100m/s에 센서 오차를 더한 기준을 사용한다. 이미 디스크에 저장한 과거 버퍼는 이력 복구에 사용한다. 사진도 요청 시각 기준 30초 이내·정확도 50m 이하의 새 위치만 붙이며 관광지 대표 좌표나 마지막 경로 점으로 대체하지 않는다.

새 추적 구간·120초 초과 GPS 공백은 지도·거리·영상에서 연결하지 않는다. 미완료 자동 기록의 시간은 기록 시작부터 마지막 좌표·사진 시각까지 계산하여 꺼진 뒤 계속 늘어나지 않게 한다. 보관된 기록은 종료 시각을 사용한다. 이 시간은 정지 구간을 포함하며 실제 이동 시간만을 뜻하지 않는다. 지도와 거리에는 센서 오차가 남고, 누락한 경로를 실제 도로에 맞춰 만들어 채우지 않는다.

Always 권한은 모든 상황의 연속 기록 보장이 아니다. 표준 위치 서비스는 시스템 종료 뒤 단독 재실행 수단이 아니므로 significant-change 감시를 복구 신호로 함께 사용한다. 해당 서비스는 약 500m 이동·5분보다 잦지 않은 수준의 신호이므로 세밀한 보행 경로 점으로 쓰지 않는다. 재실행 시 네이티브 위치 관리자를 다시 구성해야 한다. [Apple: 권한별 동작](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services), [significant-change 서비스](https://developer.apple.com/documentation/corelocation/cllocationmanager/startmonitoringsignificantlocationchanges())

앱 전환 화면에서 밀어 강제 종료하면 iOS는 사용자가 앱 실행을 원하지 않는 것으로 처리하며, 다음 직접 실행 전까지 백그라운드 재실행이 막힐 수 있다. 앱이 이 선택을 우회하거나 빠진 구간을 복구한다고 약속하지 않는다. 실제 iPhone의 장시간 잠금·재부팅·저전력·백그라운드 새로고침·정확한 위치 변경은 별도 검증 대상이다. [Apple DTS: 백그라운드 실행과 강제 종료](https://developer.apple.com/forums/thread/685525)

자동 모드는 `nearestTenMeters`, `distanceFilter=15m`, `activityType=other`, 자동 절전을 사용한다. 정지로 상세 추적이 쉬면 Always의 큰 이동 신호 또는 앱 전경 복귀로 다시 시작한다. When In Use만 허용한 경우 앱 밖의 자동 재개는 제한된다. 짧은 이동 시작 구간이 빠질 수 있으며 실제 하루 배터리 소모량은 측정하지 않았다. [Apple: 위치 사용 효율](https://developer.apple.com/documentation/xcode/accessing-the-device-s-location-efficiently)

## 개인정보·내보내기·삭제

좌표·사진을 앱 자체 서버에 업로드하지 않으며 MP4도 기기에서 만든다. 네이버 지도 표시·스냅샷에는 SDK의 인증·타일 네트워크 요청이 있으므로 앱 전체가 오프라인이라는 뜻은 아니다.

JSON 내보내기는 여권·미션·여정의 좌표·시각·정확도·사진 위치·미리보기·압축 사진 Base64를 포함한다. 사용자가 OS 공유 대상을 고른다. 카메라 원본 해상도를 보장하지 않으며 JSON 가져오기·계정 동기화는 없다.

진행 중 여정 삭제와 전체 삭제는 자동 기록을 끄고 관련 네이티브 버퍼·영상 캐시·DB 기록을 지운다. 과거 여정 하나를 삭제할 때 다른 날짜의 추적은 유지한다. 미션 보상과 여권은 개별 여정 삭제의 대상이 아니다. 앱 저장소 자체 암호화·OS 백업 제외 기능을 따로 구현한 것은 아니며 앱 삭제·데이터 초기화 시 기록을 잃을 수 있다.

MP4는 `Caches/JourneyVideos`에 놓인다. 사진 앱·파일 앱으로 내보낸 복사본은 앱의 여정 삭제와 별개다. **사진 앱에 동영상 저장**은 Photos 추가 권한을 요청하고 **파일로 저장 · 공유**는 OS 공유 화면을 연다. [Apple: 사진 접근과 사용자 동작](https://developer.apple.com/documentation/PhotoKit/delivering-an-enhanced-privacy-experience-in-your-photos-app)

## 영상 형식과 제한

- iPhone 네이티브 MP4, H.264, 720×1280 세로, 24fps, 20~45초, 무음.
- 현재 기록의 사본 또는 지난 기록에 경로 점 2개 이상이나 사진 1장 이상이 필요하다. 한 영상은 사진 최대 60장·좌표 최대 60,000개이며 초과 사진을 몰래 버리지 않는다.
- 제목·날짜·거리·경과 시간·경로·실제 보관 사진을 합성한다. 위치 없는 사진은 사진 장면에 포함하며 가짜 지도 핀을 만들지 않는다.
- 공식 네이버 스냅샷 성공 시 로고·출처를 포함한 전체 이미지를 사용한다. 실패하면 명시된 ‘기록 좌표를 연결한 그림’으로 대체하며 실제 도로망이나 내비게이션으로 표시하지 않는다.
- 영상용 지도 캡처와 실시간 지도 갱신을 직렬화해 새 GPS가 캡처에 섞이지 않게 한다. 캡처 뒤 원래 지도 상태를 복구하며 네이티브 위치 수집은 계속한다.
- 일시정지·GPS 공백은 영상에서도 연결하지 않는다. 인코딩 240초 제한과 실패 파일 정리를 적용하고 원본 여정·사진은 유지한다. [Apple: AVAssetWriter](https://developer.apple.com/documentation/avfoundation/avassetwriter)

## 자동 기록 전환 후 검증 — 2026-10-24

Node 테스트 107개, Swift XCTest 15개, 타입·린트·프로덕션 빌드가 통과했다. 390×844 브라우저에서 첫 지도 화면의 자동 기록 설정, 여정 소개·스위치·날짜별 이력과 브라우저의 비활성 스위치를 확인했으며 GPS 권한 요청은 없었다. 최신 iOS 동기화·Xcode 빌드·업데이트 설치·실행이 통과했다. 실제 네이버 지도 13곳(12곳 묶음+1곳), 자동 기록 설정 버튼·오른쪽 버튼 3개·기존 스탬프 1개와 이전 수동 기록 보존을 확인했다. [iOS 자동 기록 진입 화면](ios-automatic-overview.png)과 [브라우저 설정 소개](automatic-recording-preview.png)를 참고한다. 브라우저에는 가로 넘침과 콘솔 경고/오류가 없었다. 네이티브 좌표 터치는 `noWindowsAvailable`로 실패하여 실제 권한 토글이나 네이티브 전체 기록 흐름을 통과로 기록하지 않는다. 아래 수동 버전의 89/7 검사와 캡처를 자동 권한·날짜 전환의 완료 증거로 쓰지 않는다. 실제 iPhone의 자동 보행/차량 기록·잠금·배터리·권한 변경·카메라·Photos·파일 공유는 미검증이다.

Swift 15건은 한국 자정·사진만 있는 날짜·동의 철회·안전 중단·이전 수동 기록 이전·차량 좌표 필터 정책과 기존 실제 MP4 검사를 포함한다. 주입한 시각·좌표로 정책을 검사한 것이며 Always 권한 화면, 실제 GPS, 잠금 상태나 운영체제에 의한 종료 후 재실행을 직접 검증한 것은 아니다.

## 이전 검증 — 같은 날의 수동 기록 버전

2026-10-24 자동 기록 전환 전의 수동 버전 검토에서 TypeScript 검사와 전체 ESLint 검사가 통과했다. 전체 Node 테스트는 지도 인증 회귀 2건을 포함해 89개, 이 중 `journey*.test.ts` 27개가 통과했다. 저장·동시 병합·재실행·중복·용량 부족·종료 실패 복구·촬영 중 여정 변경·저장 후 동기화 실패 재시도·위치 없는 사진·구간별 거리·브라우저 숨김 처리를 가짜 IndexedDB와 주입한 추적기로 검사했다. 이것은 실제 GPS 이동 검증과 구분한다.

정적 프로덕션 빌드, iOS 자산 동기화, Xcode 빌드와 업데이트 설치가 성공했다. 390×844 브라우저 화면에서 정리된 수집함, 여정 소개·시작 버튼·이력 화면과 가로 넘침이 없음을 확인했다. iPhone 17 Pro / iOS 26.5 시뮬레이터의 실제 네이티브 실행 화면에서 네이버 지도, 13개 관광지 마커와 여정 표시줄을 확인했다. 이 화면 확인을 위해 새 GPS 여정 기록을 만들지는 않았다.

별도 iOS 테스트 시뮬레이터에서 XCTest 7건이 통과했다. GPS 필터·구간 분리 2건, 실제 MP4 생성 3건, 사진 수·잘못된 좌표 거부 1건, 영상 캐시 삭제 범위 1건이다. 생성한 파일을 다시 디코딩해 H.264·크기·길이와 실제 테스트 사진의 픽셀, 지도 없는 대체 영상, GPS 공백과 스냅숏 하단 보존을 검증했다. 테스트용 이미지·좌표와 임시 폴더를 사용하며 사용자의 여행 기록·영상 캐시는 시험하거나 삭제하지 않았다.

실제 iPhone의 보행 경로, 잠금 상태의 장시간 추적, 강제 종료·재부팅·저전력 모드, 권한 변경·통신 장애, 카메라 촬영부터 좌표·사진 보관까지의 전체 과정, 사진 앱 권한과 OS 공유 화면은 현장 확인이 남아 있다. 시뮬레이터에서 영상 파일을 생성한 결과를 이 항목들의 완료로 간주하지 않는다.
